# Architecture drift evidence
Date: 2026-09-08. Authority: explicit p2d request following the five-mechanism proposal.

## Outcome and scope
Ship a harness-independent Node CLI in the existing verification-scripts component, tests, and adoption guidance in documentation. It scans a consumer's explicitly declared source scope, checks ownership and forbidden textual boundary rules, writes revision/content-bound reports, and compares a prior report without rewriting it. No runtime service, scheduler, new dependency, or changes to an external application. This catalog's synthetic fixtures are the pilot; real application adoption remains local to its owner.

## Accepted contract
R1. Strict versioned JSON policy: application ID; nonempty source_roots (relative directories); nonempty extensions (such as .py, .ts); optional ignored relative subtrees; nonempty components with unique id, owner, path and responsibility; rules with unique id, description, component ID and forbidden_regex; exceptions with unique id, rule ID, component ID, owner, reason, review_by ISO date, removal_condition. Zero rules is allowed but explicitly disclosed. No glob interpretation; paths are literal repo-relative paths. Most-specific matching component owns a file. Duplicate component paths, unknown refs, malformed regex/dates and unsupported fields are invalid input.
R2. CLI: node scripts/check-architecture-drift.mjs --root <consumer> --policy <json> [--baseline <previous-report.json>] [--out <new-report.json>] [--as-of YYYY-MM-DD]. Help exits 0; no args or malformed/missing input exits 2. Findings or changed policy versus baseline exit 1. Clean explicitly scoped scan exits 0. Report output includes schema/version/tool identity, application, timestamp, as_of, Git revision and dirty state when available (unknown for non-Git), policy hash, scanned file list with SHA256/owner, counts and findings, scope/limitations. Do not print matched source contents or secrets.
R3. Only regular UTF8 source files in declared roots/extensions are scanned. Missing roots, empty scan, traversal escapes, symlink/reparse paths or unreadable inputs fail explicitly; don't silently claim success after skipping inaccessible content. Avoid .git and node_modules by default. Overlapping roots must not duplicate files. Output is create-only (no overwrite), never writes baseline or policy, and cannot overwrite scanned source. Rule engine is explicitly line-based regex matching, not an AST or automatic foreign-database detector. Rules are trusted local code-like configuration, not untrusted downloaded regex.
R4. Unowned source files and regex matches produce stable finding identities (rule/component/path; line is evidence, not identity). Repeated matches need not duplicate a finding. Exceptions annotate matching findings but never suppress them or make them green; overdue review dates are separate findings even if no current rule match. Due today is not overdue. Missing referenced rule/component is invalid input. A report never certifies semantic architectural conformance.
R5. Compare same-application validated report formats; reject malformed or tampered reports. Bind report contents with a reproducible SHA256 digest (integrity only, not authenticity). Return new/resolved/persisting findings, file additions/removals/changes and deltas for files/components/rules/exceptions/dependencies where deterministically available. For v1 dependency counts are optional: if unsupported say unavailable, never infer zero. A policy hash change is a blocking policy_changed finding and invalidates like-for-like comparison; still show observed deltas honestly. Baseline cannot be silently reblessed. Applications review baseline/policy changes separately in their normal PR process; this CLI cannot authenticate an approver.
R6. Guide review of changed ownership, deviation removal dates, complexity signals (not arbitrary maximums), invariant-negative tests, and a periodic real workflow diagnosis/recovery trace. Do not implement notifications or a monitoring service.
R7. Tests exercise CLI subprocess boundaries and synthetic consumers, including Python and TS text; forbidden rule mutation fails; config deletion/weakening triggers policy change; malformed baseline and different application fail; file removal appears in comparison; changing a line number does not invent a new finding; no-write guarantees and traversal/link handling are covered.
R8. Integrate a narrow npm test:drift command and aggregate npm test; existing UI checks must still pass. Document exact limits and usable commands.
## Cost and prior art
Existing scripts/check-ui-surface-catalog.mjs checks declarations with Ajv but has no source inventory/history. Existing config/architecture-components.json is catalog component ownership, not a consumer drift policy. KB's external architecture-drift checks undeclared components but is harness-specific and lacks this report/history contract. Reuse Node built-ins and existing test conventions, no new dependencies; small new code is needed in existing verification-scripts.
## Assumptions
A scoped text-rule checker is the smallest useful portable first implementation; it intentionally cannot resolve imports dynamically or detect semantic duplicated policy. Real domain/API contract tests remain consumer-owned. No automatic cadence is requested.
## Requirements assurance
All load-bearing behavior is specified above; repository and scripts inspected. No product question blocks this bounded implementation. One integrated CLI review follows passing tests. Requirements-wide extra review not required because scope, outputs, failure semantics, authority, and limits are explicit.
